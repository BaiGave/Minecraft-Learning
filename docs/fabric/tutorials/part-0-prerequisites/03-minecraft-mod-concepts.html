第三章：Minecraft Mod 开发概念

在开始写代码之前，先来了解一下 Mod 开发的基本概念。

目录

  • 什么是 Mod？

1. 什么是 Mod？

1.1 Mod = Modification（修改）

Mod 就是对 Minecraft 游戏的"修改"或"扩展"：

原版 Minecraft                    添加 Mod 后
┌─────────────────┐              ┌─────────────────┐
│  石头就是石头    │      →       │  石头可以发光    │
│  只能砍树       │              │  可以自动砍树    │
│  只有 10 种矿石 │              │  有 100 种新矿石 │
└─────────────────┘              └─────────────────┘

1.2 Mod 能做什么？

类别示例说明
新方块/物品各种新方块、新装备最常见的 Mod 类型
新生物史莱姆少女、合成生物增加游戏趣味性
新维度魔法世界、太空全新游戏体验
性能优化Sodium、Iris让游戏更快更好
工具/管理REI、WTHIT提供游戏辅助信息

2. Fabric 是什么？

2.1 Mod Loader 家族

Minecraft Mod 开发有两大主流框架：

框架特点生态
Fabric轻量、现代化、Mod 兼容性高Sodium、Iris、REI
Forge功能强大、历史悠久、Mod 数量多JEI、AE2、Thaumcraft

2.2 为什么选择 Fabric？

选择 Fabric 的理由：

✅ 轻量级 - 对游戏性能影响小
✅ 现代化 - 使用最新 Java 版本
✅ 兼容性好 - 容易和其他 Mod 共存
✅ 开发简单 - API 设计清晰易用
✅ 社区活跃 - 文档丰富，帮助多

2.3 Fabric 生态系统

┌─────────────────────────────────────────┐
│              Minecraft 游戏                │
├─────────────────────────────────────────┤
│  ┌─────────────────────────────────┐    │
│  │         Fabric Loader           │    │
│  │    (负责加载和初始化 Mod)        │    │
│  ├─────────────────────────────────┤    │
│  │         Fabric API              │    │
│  │    (提供开发用的各种工具)         │    │
│  ├─────────────────────────────────┤    │
│  │        Mixin                    │    │
│  │    (修改游戏原有代码)            │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
                  ↑
         ┌────────┴────────┐
         │     你的 Mod      │
         │   (使用 Fabric)   │
         └──────────────────┘

3. Mod Loader 的作用

3.1 Mod Loader 做什么？

Mod Loader 就像一个"管理员"，负责：

1. 发现 Mod        → 扫描 mods 文件夹，找到所有 Mod
2. 加载 Mod         → 读取 Mod 的代码和配置
3. 初始化 Mod       → 执行 Mod 的初始化代码
4. 处理依赖         → 确保 Mod 加载顺序正确
5. 协调 Mod         → 处理 Mod 之间的交互

3.2 游戏启动流程

普通启动                              有 Mod 时
────────────────────────────────────────────────
1. 启动游戏                           1. 启动游戏
2. 加载原版代码                       2. Fabric Loader 启动
3. 进入主菜单                         3. 发现并加载 Mod
                                     4. Mod 初始化
                                     5. 进入主菜单

4. API 和 Mixin 是什么？

4.1 API = Application Programming Interface（应用程序接口）

API 就是 Mod 开发者使用的"工具箱"：

Fabric API 提供的工具箱包含：

┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   方块 API    │  │   物品 API    │  │   实体 API    │
│  创建新方块   │  │  创建新物品   │  │  创建新生物   │
├──────────────┤  ├──────────────┤  ├──────────────┤
│   事件 API    │  │   命令 API    │  │   网络 API    │
│  监听游戏事件 │  │  创建新命令   │  │  多人联机通信 │
└──────────────┘  └──────────────┘  └──────────────┘

4.2 Mixin 是什么？

Mixin 是一种"代码注入"技术，可以修改游戏的原有代码：

原版代码（不能直接修改）：
┌─────────────────────────┐
│ void 攻击() {            │
│   造成 5 点伤害;        │  ← 这段代码是原版
│   播放音效;              │
│ }                        │
└─────────────────────────┘

使用 Mixin 注入：
┌─────────────────────────┐
│ void 攻击() {            │
│   造成 5 点伤害;        │  ← 原版代码
│   [新代码：爆炸效果]     │  ← Mixin 添加的新代码
│   播放音效;              │
│ }                        │
└─────────────────────────┘

4.3 API 和 Mixin 的区别

APIMixin
用途提供新功能修改现有功能
安全性高，不会破坏原版中，需要小心
难度简单易用较复杂
示例register() 创建物品修改方块放置逻辑

5. 服务端 vs 客户端 Mod

5.1 两者的区别

特性服务端 Mod客户端 Mod
运行环境专用服务器单人/多人客户端
是否必须所有人必须安装可以不装
对其他人影响影响所有玩家只影响自己
典型用途新物品、新系统着色器、UI 增强

5.2 常见误区

❌ 误区：我加了一个新方块，所有人都能看到
✅ 正确：只有安装了 Mod 的玩家能看到

❌ 误区：在服务端加 Mod，所有人必须玩
✅ 正确：服务端 Mod 需要所有玩家都安装

❌ 误区：客户端 Mod 可以加到服务器上
✅ 正确：大多数客户端 Mod 只能装在客户端

5.3 开发选择

初学者建议：
├── 从客户端 Mod 开始
│   └── 可以单人测试，不需要服务器
│
└── 进阶后尝试
    └── 服务端 + 客户端协同开发
        └── 需要架设测试服务器

6. 数据包和资源包

6.1 什么是数据包？

数据包（Data Pack）用于定义游戏数据，不需要写 Java 代码：

数据包可以定义：
├── 配方         →  工作台配方
├── 战利品表     →  击杀生物掉落什么
├── 标签         →  哪些方块算"木头"
├── 生物生成     →  生物在哪里生成
└── 进度         →  成就系统

6.2 什么是资源包？

资源包（Resource Pack）用于定义游戏外观和声音：

资源包可以定义：
├── 模型         →  方块/物品长什么样
├── 纹理         →  方块/物品的图片
├── 语言         →  显示的文字
├── 声音         →  音效和音乐
└── 着色器       →  特殊视觉效果

6.3 在 Mod 中的位置

你的 Mod
├── Java 代码
│   ├── 注册方块/物品逻辑
│   ├── 事件处理
│   └── 游戏机制
│
├── 数据包 (src/main/resources/data/)
│   ├── recipes/           配方
│   ├── loot_tables/       战利品表
│   └── tags/              标签
│
└── 资源包 (src/main/resources/assets/)
    ├── models/            模型
    ├── textures/          纹理
    └── lang/              语言文件

7. 理解 Mod 结构

7.1 最小 Mod 需要什么？

一个最简单的 Mod 需要：

1. fabric.mod.json          Mod 描述文件
2. 一个 Mod 主类             初始化代码

其他都是可选的！

7.2 fabric.mod.json 示例

{
    "schemaVersion": 1,
    "id": "my-first-mod",           // Mod 的唯一 ID
    "version": "1.0.0",               // 版本号
    "name": "My First Mod",          // 显示名称
    "description": "这是我做的第一个 Mod！",
    "authors": ["YourName"],         // 作者
    "contact": {
        "homepage": "https://example.com"
    },
    "license": "MIT",
    "icon": "assets/my-first-mod/icon.png",  // 图标
    "environment": "*",              // 环境：* 表示所有环境
    "entrypoints": {
        "main": [
            "net.example.mymod.MyMod"    // 主类入口
        ]
    },
    "depends": {
        "fabricloader": ">=0.15.0",  // 依赖
        "minecraft": "~1.21",
        "java": ">=21"
    }
}

7.3 Mod 主类示例

public class MyMod implements ModInitializer {

    @Override
    public void onInitialize() {
        // 这个方法在 Mod 加载时会被调用
        // 写在这里的代码会在游戏启动时执行

        System.out.println("我的 Mod 加载成功了！");
    }
}

7.4 完整项目结构

my-first-mod/
├── src/
│   └── main/
│       ├── java/
│       │   └── net/
│       │       └── example/
│       │           └── mymod/
│       │               ├── MyMod.java              ← Mod 主类
│       │               ├── block/                  ← 方块相关
│       │               ├── item/                   ← 物品相关
│       │               └── event/                  ← 事件处理
│       │
│       └── resources/
│           ├── fabric.mod.json               ← Mod 配置
│           └── assets/                        ← 资源文件
│               └── my-first-mod/
│                   ├── lang/                   ← 语言文件
│                   ├── models/                  ← 模型文件
│                   └── textures/               ← 纹理图片
│
├── build.gradle                     ← 构建配置
└── gradle.properties               ← Gradle 配置
