核心概念

光照是什么？

生活比喻：

想象你在一个漆黑的房间里：

  • 手电筒 = 发光的方块（火把、南瓜灯）
  • 窗户 = 天空光照的来源
  • 墙壁和家具 = 会阻挡光照的方块

Minecraft 的光照系统 = 模拟现实世界光线的传播！

两种光照

flowchart LR subgraph SkyLight["天空光照 Sky Light"] direction TB S1["来源：天空"] S2["向下传播"] S3["被不透明方块阻挡"] end subgraph BlockLight["方块光照 Block Light"] direction TB B1["来源：发光方块"] B2["向所有方向传播"] B3["可穿过透明方块"] end subgraph Result["最终光照"] direction TB R1["取两者最大值"] R2["最终亮度 = max(天空光, 方块光)"] end SkyLight --> Result BlockLight --> Result
类型来源特点例子
天空光照天空只向下，阻挡即消失白天
方块光照发光方块向所有方向，可穿透明方块火把、岩浆

为什么不直接计算光照？

生活比喻：

想象你要计算一个城市的交通流量：

  • 实时计算 = 每辆车每秒钟都在变 → 计算量爆炸 💥
  • 预计算+增量更新 = 只计算变化的区域 → 完美！

flowchart TD subgraph Naive["实时计算（不可行）"] direction TB N1["每帧计算所有方块的光照"] N2["复杂度：O(n³)"] N3["1万个方块 = 10亿次计算/帧"] N4["60帧/秒 = 60亿次/秒 💥"] end subgraph Minecraft["Minecraft 的方案"] direction TB M1["光照值存储在 Chunk 中"] M2["只更新变化区域"] M3["使用 BFS 传播算法"] M4["复杂度：O(变化方块数)"] end

光照是否需要更新

50:    public static boolean needsLightUpdate(BlockView blockView, BlockPos pos,
51:                                            BlockState oldState, BlockState newState) {
52:        // 如果方块状态没变，不需要更新
53:        if (newState == oldState) {
54:            return false;
55:        }
56:
57:        // 检查透明度、光照值、是否有方向透明度变化
58:        return newState.getOpacity(blockView, pos) != oldState.getOpacity(blockView, pos)
59:            || newState.getLuminance() != oldState.getLuminance()
60:            || newState.hasSidedTransparency()
61:            || oldState.hasSidedTransparency();
62:    }

传播算法核心

光照使用 BFS（广度优先搜索） 传播：

99:    protected void enqueueLightUpdate(long blockPos, long flags) {
100:        // 将方块加入传播队列
101:        this.lightQueue.enqueue(blockPos);
102:        this.lightQueue.enqueue(flags);
103:    }
184:    private int processLightQueue() {
185:        int updates = 0;
186:
187:        // 处理待传播的光照
188:        while (!this.lightQueue.isEmpty()) {
189:            long blockPos = this.lightQueue.dequeueLong();
190:            long flags = this.lightQueue.dequeueLong();
191:
192:            // 传播光照到相邻方块
193:            this.propagateLight(blockPos, flags);
194:            updates++;
195:        }
196:
197:        return updates;
198:    }

小结

概念说明
天空光照从天空向下传播，被阻挡即消失
方块光照从发光方块向所有方向传播
NibbleArray压缩存储光照值（每方块4位）
BFS传播从光源向外逐层传播光照
增量更新只更新变化的区域
关键理解：
  • 光照是预计算的：不实时计算，而是存储在Chunk中
  • 天空光和方块光独立：最终取两者最大值
  • 变化触发更新：放置/破坏方块时才重新计算
